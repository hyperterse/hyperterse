Hyperterse agents are declarative A2A runtimes discovered from your project
filesystem, just like tools. You define agent behavior in config files,
Hyperterse compiles and validates them, then mounts each agent behind a
dedicated HTTP route prefix.

## What you get

- **Declarative agent discovery** from `app/agents/**/config.terse`
- **Compile-time permission checks** for tool access policies
- **Per-agent A2A endpoints** for agent card, JSON-RPC, streaming, tasks, and
  push config
- **Multi-provider model config** for Gemini, Vertex AI, and OpenAI-compatible backends

## How the system fits together

```text
.hyperterse
app/
  tools/
    get-orders/config.terse
  agents/
    support/config.terse
```

1. Compiler discovers tools and agents.
2. Tool access policy is resolved (`inherit` / `allow_*`).
3. Agent definitions are compiled into runtime model.
4. Runtime mounts A2A endpoints under `/agent/{agentName}`.

## Endpoint shape per agent

Every compiled agent gets:

- `GET /agent/{agentName}/.well-known/agent-card.json`
- `POST /agent/{agentName}`

<Tip>
  Agent endpoints are separate from MCP `/mcp`. Use MCP for tool-native
  workflows, and use `/agent/*` when you need A2A agent behavior.
</Tip>
